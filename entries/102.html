🧱 工具脱钩

Claude Code 一周两面受敌——为一边合规写的代码，在另一边成了“后门”

✗ 已公开修正判断台账

脱钩这次不是从政府禁令开始的，是从一家大厂的采购名单开始的。国产编码 agent 的企业窗口就此打开。

6 月底开发者逆向发现 Claude Code 内置检测机制，查时区和代理、识别中国相关用户；官方称属 3 月上线的「实验性」措施、7/2 已删。重的在后面：7/8 工信部 NVDB 发风险提示，定调「安全后门、危害严重」；7/10 起阿里内部全面禁用，列入高风险软件名单。

对创业者：做国产编码 agent 的，把「可审计、可本地部署、可断供生存」做成产品首页三条，现在就去接大厂的替换预算，这是有 deadline 的采购需求。对投资人：中国区开发工具的尽调加一条「供应商国别与断供预案」；收入高度依赖美系模型 API 的中国标的调低估值，风险出在采购决策，跟技术好坏无关。

脱钩第一次不需要禁令，一纸风险提示就够了。

补记
2026-11-13 补对账，本条验收早在 8/14 到期，此前漏对：一个月验收的读数是 0，阿里之外没有第二家大厂跟进禁用 Claude Code；字节 8 月的表态是禁止蒸馏美国模型，并非禁用。证伪口的另一半「Claude API 在华中转用量未降」没有可核的数据源。按验收口记 ✗ 认错：按本篇写的节奏，「采购层脱钩」是过度外推。迟到的读数：观点网、搜狐 11/4–5 报道，字节 11 月起限制员工用 Claude、Codex 等外部 AI 工具接触内部代码和飞书文档，字节知情人士称非工作场景不受限。这比窗口晚了约三个月，对 Claude 和 OpenAI 一视同仁，理由是数据安全而不是「后门」，不追认。
