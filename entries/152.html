Kimi 名次换不来自营量：OpenRouter 份额剩一成

Kimi 名次换不来月之暗面自营 API 的量。K3.1 Pro 10/23 发布即排 Artificial Analysis 总榜第 4；11/4 放权重，到 11/13 OpenRouter 上自营请求份额从全部掉到约一成（自算），量少一大半（推断）。

托管方接走的量，收钱全看 11/4 公开的许可证：含关联方年收入超 2000 万美元的托管方商用前另签协议，条款没公开。ENTRY 112 我说钱在自营 API 等处收，改口：它在 OpenRouter 留不住量，这一成还会往下走。

对投资人：月之暗面收入拆成国内订阅、自营 API、托管分成三栏，自营按放权重后的量算，分成条款没披露不给溢价。对创业者：用 K3.1 做后端，先问托管方是不是认证伙伴、有没有另签协议，合同写死吞吐和 SLA。

证伪口
起算 2026-11-13（补记写作日），读数和窗口都从这天开始算，之前的读数不计，至 2027-01-23。只裁定正文这一句：「它在 OpenRouter 留不住量，这一成还会往下走」（「它」指月之暗面自营 API）。裁定源分两侧（按 ENTRY 127 公开规则，证伪口不单挂第三方指标）。甲侧：OpenRouter 网页前端接口 /api/frontend/v1/stats/endpoint（无公开文档；permaslug moonshotai/kimi-k3.1-pro-20261023，variant standard，不含 :batch 变体），读各 endpoint 近 30 分钟的请求数；作者每天北京时间 06:00 至 07:00 拉一次，原始 JSON 存进仓库归档；当日读数 = 月之暗面自营两个 endpoint（标准版与 Highspeed）请求数之和 ÷ 全部 endpoint 请求数；现值约 9.6%（11/13 北京时间 06:25 至 06:40 三次读数 10.7%、9.3%、8.7% 的均值，自算）；K3 自营读数 7.3%（只有一个自营 endpoint，口径不同，见口径注）。乙侧：月之暗面官方公告、上市申请文件或具名高管采访原文中，对 11/4 放权重后海外自营 API 收入或调用量的披露。终审看 2026-12-25 至 2027-01-23 这 30 天甲侧日读数的均值：✗：甲侧均值不低于 9.6%（现值，说明份额没有往下走），或乙侧在 2027-01-23 前披露放权重后海外自营 API 收入或调用量高于放权重前，任一成立即撤回「它在 OpenRouter 留不住量，这一成还会往下走」，对 ENTRY 112 的修正降级为「放权重第 9 天的读数」；已验证：甲侧均值不高于 7.3%（K3 自营读数水平，口径不同，见口径注），且乙侧到期没有相反披露；⏳：介于两者之间，到期转为「未裁定」并公开读数。其间每周公开一次读数，状态记 ⏳。K3.1 Pro 仍在月之暗面官方 API 在售、只撤下 OpenRouter 自营 endpoint 的，当日读数按 0 计；因发布后继版本而下线或改路由 K3.1 Pro 自营 endpoint 的，属例行换代，自下线日起按源缺失处理，不按 0 计，并公开说明。源缺失：甲侧接口改版时，改读模型页服务端 HTML 内嵌的同一组 endpoint 请求数（11/13 抓取可见），它与甲侧同源，只算备用读法，不算并行来源；OpenRouter 整体停止公开这组数据时，只按乙侧裁定 ✗，不再给已验证；终审窗口甲侧缺读超过 5 天，改用起点不早于 11/13、缺读不超过 5 天的最近一个完整 30 日窗口；仍然没有合格窗口、乙侧也没有披露，记「未裁定·源缺失」并关闭本条。只记读数、不裁定：这把尺子量的是请求数而非 token，OpenRouter 默认按价格加权分流，价格会被量进去，按吞吐排序要用户指定；终审窗口跨美国年末假期，固定时刻读数受季节性影响；月之暗面调价，或签下新算力后（如 CNBC 11/5 报道的欧洲 Blackwell 洽谈落地），读数照常记录；只算标准 endpoint 的份额（11/13 均值约 6.1%）；月之暗面自营标准 endpoint 的 p50 吞吐排名（11/13 为 23 个 endpoint 中最慢，28 至 29 tok/s）；Bedrock 是否上架 K3.1 Pro 标准版，Azure 或 Vertex 是否上架；月之暗面上市申请文件若只披露分渠道收入或托管分成条款、不涉及放权重前后的海外自营 API，只记录。
