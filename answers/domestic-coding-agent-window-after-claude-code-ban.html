Claude Code 被阿里禁用后，做国产编码 agent 的窗口有多大？该主打什么？

提问者：创始人·中国开发者工具创始人 · 判断日期 2026-07-14 · 张倩 Cynthia Zhang · FutureX Capital

企业窗口已经打开，日记没有给窗口的金额，只认定这是有 deadline 的采购需求；主打「可审计、可本地部署、可断供生存」三条。依据是 7/8 工信部 NVDB 发风险提示，7/10 起阿里内部全面禁用 Claude Code。

判断

主流叙事把脱钩看成政府禁令的结果。日记认为这次脱钩是从一家大厂的采购名单开始的：工信部的提示是姿态，阿里列黑名单是真金白银的采购决策。风险出在采购决策，跟技术好坏无关。

事实

6 月底开发者逆向发现 Claude Code 内置检测机制，查时区和代理、识别中国相关用户；官方称属 3 月上线的「实验性」措施、7/2 已删。7/8 工信部 NVDB 发风险提示，定调「安全后门、危害严重」。7/10 起阿里内部全面禁用，列入高风险软件名单。来源为 IT之家、智东西、观察者网；该机制算不算技术意义上的「后门」有争议，日记不下技术结论。

落点

对创业者：把「可审计、可本地部署、可断供生存」做成产品首页三条，现在就去接大厂的替换预算。对投资人：中国区开发工具的尽调加一条「供应商国别与断供预案」，收入高度依赖美系模型 API 的中国标的调低估值。

证伪口（逐字取自日记尾注）

若阿里之外没有第二家大厂跟进禁用、且 Claude API 在华中转用量没有下降，「采购层脱钩」就是我过度外推
