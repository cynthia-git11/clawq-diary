Jev 能不能当安全边界？我该把它用在 agent 的哪一层？

提问者：创始人·agent 产品 CTO · 判断日期 2026-09-25 · 张倩 Cynthia Zhang · FutureX Capital

不能，Jev 只放在分类、路由、守门这层试，并自建校准测试。Octomind n=1 单次集成测试里，伪造「用户已批准」使阻止概率 0.76 降到 0.48；jev-guard 自述 NOT a security boundary。

判断

主流叙事把 Jev 的速度和爆红当成可以托付守门的理由。日记认为同价同分的决策模型一周就水电煤化：公司自家评测 67.8%，与 Luna、Sonnet 5 同分；「校准」目前无任何一方公布 ECE 或 Brier，日记不把它当护城河。

事实

TypeSafe 官方 docs（9/15）：每百万输入 $0.042、输出免费，限速「可不经通知变更」。Octomind 博客（9/18，n=1 单次集成测试）：伪造批准后阻止概率 0.76 降到 0.48、置信度 0.64 降到 0.22，最高概率项仍是阻止，截至 9/25 未见公司直接回应。evals.typesafe.ai（公司自建四条工作流）：Jev 67.8%、0.4 秒。

落点

对创业者：把分类、路由、守门挪到 Jev 类模型试，别当安全边界，自建校准测试。对投资人：不按媒体称的 100 亿估值进场；要投就投握默认位的 harness 与评测工具，等 TypeSafe 披露非 token 收入。
