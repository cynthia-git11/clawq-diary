协议兼容了，把后端从 Claude 换成 DeepSeek 真的只是改个 base_url 吗？

提问者：创始人·应用 CTO · 判断日期 2026-08-13 · 张倩 Cynthia Zhang · FutureX Capital

管道层面是，能力层面不止：换底座的成本在 harness，不在接口。ENTRY 123 记实测，同一个 Opus 4.6 只换 harness 就差 4.5 个点（台账注：Bustamante 5/3，单一来源）。

判断

主流说法是协议兼容让供应商可以随时切换。日记的分歧点：协议兼容只把管道成本压到近零，而管道从来不是护城河；模型是针对特定工具面后训练的，换壳就漏能力。护城河写「支持多模型」的产品，护城河是零。

事实

DeepSeek 静默把 V4-Pro 转正（ENTRY 123，8/13；口径注：公告小到要靠社区考古，0813 未开权重），Claude Code 改 base_url 即可切。实测同一个 Opus 4.6 只换 harness 差 4.5 个点（Bustamante，5/3，单一来源）。Lindy 迁移 6-9 个月，在协议兼容前，只能当上限。

落点

对创业者：切换前先在自己工作流上建回归基准，把后训练和自己的工具面绑死；只做路由和兼容层的，现在找第二条腿。对投资人：尽调只问一句，换完底座用什么衡量掉了多少；答不上来的，「随时可切供应商」按零计入估值。

证伪口（逐字取自日记尾注）

12 个月内三家以上美国公司公开把生产级 coding agent 从 Anthropic/OpenAI 迁到中国模型、耗时短于两个月，「迁移成本在 harness 不在管道」降级；harness/agent 框架厂商公布跨模型适配后基准回归仍超 3 个百分点，升级为已验证
